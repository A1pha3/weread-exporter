## 1.1 导出格式详解

weread-exporter 支持五种输出格式，每种格式都有其独特的技术特点和适用场景。理解这些格式的本质区别，将帮助你在不同需求下做出最佳选择。本节将详细介绍每种格式的技术原理、实现方式、优缺点，以及最佳使用建议。

### 1.1.1 EPUB 格式深度解析

EPUB（Electronic Publication）是国际数字出版论坛制定的开放电子书标准，是目前最广泛使用的电子书格式之一。weread-exporter 使用 EbookLib 库来生成 EPUB 文件，该库提供了完整的 EPUB 规范实现。理解 EPUB 的技术结构，有助于你更好地理解工具的工作原理，并在出现问题时进行排查。

EPUB 文件本质上是一个带有特定目录结构的 ZIP 压缩包。标准 EPUB 结构包含几个核心组件：META-INF 目录下的 container.xml 文件告诉阅读器 EPUB 内容的位置；OEBPS 目录下的 content.opf 文件描述了整个出版物的元数据和资源关系；toc.ncx 文件提供了目录导航功能；各章节内容则以 XHTML 格式存储。weread-exporter 在生成 EPUB 时会构建这个完整的结构，确保文件符合规范。

EPUB 格式的主要优势在于其灵活性和可重排版特性。EPUB 阅读器可以根据屏幕大小自动调整字体大小和段落布局，这使得同一本书可以在不同设备上获得良好的阅读体验。EPUB 还支持嵌入字体、矢量图形、交互式元素等高级特性，是功能最丰富的电子书格式之一。weread-exporter 生成的 EPUB 文件保留了原书的结构层次，包括章节目录、图片资源、代码块等元素。

然而，EPUB 格式也有其局限性。由于是流式布局，某些固定的页面格式（如复杂表格、艺术字标题）可能无法完美还原。此外，EPUB 是纯文本格式，不包含 DRM 保护，导出后的文件可以被自由复制。weread-exporter 生成的 EPUB 文件不包含任何版权保护信息，使用时请注意版权问题。

在使用 weread-exporter 导出 EPUB 时，你可以通过以下命令指定：

```bash
weread-exporter -b 书籍ID -o epub
```

工具会在 output 目录下生成名为「书籍标题.epub」的文件。如果不指定输出格式，默认也会导出 EPUB。

### 1.1.2 PDF 格式深度解析

PDF（Portable Document Format）是 Adobe 公司开发的便携文档格式，以其「所见即所得」的特性著称。weread-exporter 使用 WeasyPrint 库将 Markdown 内容渲染为 PDF。WeasyPrint 是一个基于 CSS 的页面渲染引擎，能够将 HTML/CSS 转换为 PDF 文件。

PDF 格式的核心特点是固定布局。PDF 文档中的每一页都精确固定，这与 EPUB 的流式布局形成对比。固定布局的优势在于能够精确还原原书的页面设计，包括页眉页脚、脚注尾注、分栏布局等复杂排版。weread-exporter 的 PDF 导出使用预定义的 CSS 样式表，尽可能还原原书的阅读体验。

weread-exporter 在导出 PDF 时支持图片格式的选择。Windows 系统默认使用 PNG 格式，因为 Windows 的图形处理库对 PNG 支持更好；Linux 和 macOS 系统则使用 JPG 格式，以获得更小的文件体积。这个默认行为可以通过源码修改来调整。如果书籍包含大量图片，PDF 文件的体积可能会比较大，这是正常的。

PDF 格式的主要优势是完美的排版还原和广泛的兼容性。几乎所有平台都有 PDF 阅读器，文件可以在任何设备上保持一致的显示效果。PDF 是正式文档、报告、书籍打印的首选格式。

PDF 格式的局限主要体现在文件体积和编辑难度方面。由于需要存储完整的页面信息，PDF 文件通常比同等内容的 EPUB 或 Markdown 大很多。此外，PDF 是只读格式，提取或修改内容需要专门的工具。

```bash
weread-exporter -b 书籍ID -o pdf
```

需要注意的是，PDF 导出依赖 WeasyPrint 库，该库在某些系统上可能需要额外的系统依赖。如果遇到 WeasyPrint 相关错误，请查阅故障排除章节。

### 1.1.3 MOBI 格式深度解析

MOBI 是 Amazon Kindle 设备使用的专有电子书格式。虽然 Amazon 已经停止支持新的 MOBI 文件（Kindle 现在主要使用 KFX 格式），但 MOBI 仍然是兼容性最好的 Kindle 格式，被所有 Kindle 设备支持。

weread-exporter 导出 MOBI 时，实际上是先生成 EPUB 文件，然后使用 Amazon 提供的 kindlegen 工具进行转换。kindglen 是一个命令行工具，能够将 EPUB 格式转换为 Kindle 支持的 MOBI 格式。这个转换过程会保留大部分格式信息，但由于 MOBI 格式本身的限制，某些高级特性（如复杂的排版）可能会丢失。

需要特别注意的是，kindlegen 工具只有 Linux 版本。这意味着在 Windows 和 macOS 系统上，默认情况下无法直接导出 MOBI 格式。当你在这些系统上尝试导出 MOBI 时，工具会显示错误信息，提示需要使用 Linux 系统或手动转换。

```bash
weread-exporter -b 书籍ID -o mobi
# 或者同时导出 EPUB 和 MOBI
weread-exporter -b 书籍ID -o epub -o mobi
```

当导出 MOBI 时，工具会自动先导出 EPUB，然后再转换为 MOBI。生成的 EPUB 文件也会保留在 output 目录中。

MOBI 格式的主要优势是广泛的 Kindle 设备兼容性。如果你需要在 Kindle 上阅读导出的书籍，MOBI 是最可靠的选择。MOBI 支持 Kindle 的字典查询、书签、标注等功能，体验与原生电子书基本一致。

MOBI 格式的局限包括：不支持某些高级排版特性、文件体积通常比 EPUB 大、以及 Amazon 可能在未来停止对 MOBI 的支持。对于新项目，建议考虑使用 EPUB 或 KF8（Kindle 较新的格式）等更开放的格式。

### 1.1.4 TXT 格式深度解析

TXT（Plain Text）是纯文本格式，不包含任何格式信息、图片或样式。weread-exporter 导出 TXT 时，会使用 BeautifulSoup 库解析 HTML 内容，提取纯文本并去除所有格式标记。

TXT 格式极其简单，所有文字都以纯文本形式存储，没有任何特殊格式。这种极简带来了最大的兼容性：任何设备、任何操作系统、任何文本编辑器都能打开 TXT 文件。TXT 文件的体积也最小，适合在存储空间有限的情况下使用。

```bash
weread-exporter -b 书籍ID -o txt
```

TXT 格式的主要用途是内容备份或进一步处理。由于没有格式信息，TXT 文件可以很容易地用脚本处理、导入到笔记软件、或进行文本分析。对于需要二次创作或引用的场景，TXT 是最灵活的格式。

然而，TXT 格式的局限也很明显：所有排版信息都会丢失，包括标题层级、粗体斜体、图片内容等。导出后的 TXT 文件只包含文字内容，结构和视觉样式都无法保留。因此，TXT 不适合作为最终阅读格式，更适合作为中间格式或备份。

weread-exporter 在导出 TXT 时会尽量保留文字内容的结构，通过添加空行来表示章节分隔。但这不是真正的结构信息，只是视觉分隔。

### 1.1.5 Markdown 格式深度解析

Markdown 是一种轻量级标记语言，用简单的语法描述格式。weread-exporter 导出的 Markdown 文件保留了章节结构、代码块、图片引用等元素，是一种结构化的纯文本格式。

Markdown 格式的核心优势是可读性和可编辑性。Markdown 源码看起来几乎就是纯文本，即使不加渲染也能理解内容结构。同时，Markdown 可以被众多应用渲染为格式丰富的文档，兼容各种笔记软件、静态站点生成器、文档系统等。

weread-exporter 导出 Markdown 时会生成两种文件：一种是合并后的完整 Markdown 文件（.md），另一种是分章节的 Markdown 文件集（保存在 cache/书籍ID/chapters/ 目录）。分章节的文件便于单独处理或选择性使用，合并后的文件则适合完整阅读。

```bash
weread-exporter -b 书籍ID -o md
```

Markdown 文件中的图片引用会被转换为本地路径，图片资源则下载到 images/ 目录。这种方式保持了文件的可移植性，移动整个项目目录时图片引用不会失效。

Markdown 格式的主要用途包括：内容二次编辑、笔记整理、静态站点生成、知识管理等。由于 Markdown 是纯文本，非常适合用 Git 进行版本控制，追踪内容的修改历史。

Markdown 格式的局限在于图片处理。weread-exporter 将图片保存为本地文件，需要维护图片与 Markdown 文件的相对路径关系。如果手动移动文件，可能会导致图片引用失效。解决方案是将 Markdown 文件和 images 目录一起移动。

### 1.1.6 格式选择决策矩阵

根据不同的使用场景，选择最合适的导出格式可以事半功倍。以下决策矩阵总结了各种场景下的推荐格式：

| 使用场景 | 推荐格式 | 说明 |
|----------|----------|------|
| 通用电子书阅读 | EPUB | 最好的兼容性和阅读体验 |
| 打印或正式文档 | PDF | 精确还原页面布局 |
| Kindle 设备阅读 | MOBI | 最好的 Kindle 兼容性 |
| 笔记整理或二次创作 | Markdown | 结构化纯文本，可编辑 |
| 简单备份或文字提取 | TXT | 最小的文件体积，最好的兼容性 |

在实际使用中，你可能需要同时导出多种格式。weread-exporter 支持一次性指定多种输出格式：

```bash
# 导出多种格式
weread-exporter -b 书籍ID -o epub -o pdf -o md

# 常见组合
weread-exporter -b 书籍ID -o epub -o pdf  # 通用 + 打印
weread-exporter -b 书籍ID -o mobi         # Kindle 专用
weread-exporter -b 书籍ID -o md -o txt    # 文字处理专用
```

选择格式时还需要考虑书籍内容的类型。对于包含大量图片和复杂排版的书籍，PDF 是最佳选择，它能最好地还原视觉效果。对于纯文字内容，EPUB 或 Markdown 可能更合适，它们提供了更好的重排版能力。

## 1.2 命令行参数详解

weread-exporter 提供了丰富的命令行参数，允许你精细控制导出行为。本节将详细介绍所有参数的含义、用法和注意事项，帮助你充分利用工具的灵活性。

### 1.2.1 基础参数

基础参数是使用频率最高的参数，包括书籍 ID 指定和输出格式选择。这些参数是导出的核心配置，必须正确设置才能完成基本导出功能。

`-b` 或 `--book-id` 参数用于指定要导出的书籍 ID。这是必选参数，可以是单本书籍的 ID（不含下划线），也可以是书单 ID（包含下划线）。工具会自动识别 ID 类型并采取相应的处理逻辑。

```bash
# 导出单本书籍
weread-exporter -b 08232ac0720befa90825d88

# 导出整个书单
weread-exporter -b 12345_67890
```

`-o` 或 `--output-format` 参数用于指定输出格式。这个参数可以多次使用以同时导出多种格式。如果不指定，默认为 EPUB 格式。

```bash
# 单一格式
weread-exporter -b 书籍ID -o epub

# 多种格式
weread-exporter -b 书籍ID -o epub -o pdf -o md
```

支持的值包括：md（Markdown）、epub（EPUB）、pdf（PDF）、mobi（MOBI）、txt（TXT）。

### 1.2.2 超时与间隔参数

导出过程中需要加载网页内容，这些参数用于控制加载超时和请求间隔。合理设置这些参数可以提高导出成功率，避免因网络波动导致的失败。

`--load-timeout` 参数设置加载章节页面的超时时间，单位为秒，默认值是 60 秒。对于网络较慢或页面较大的情况，可以适当增加超时时间。

```bash
# 设置较长的超时时间
weread-exporter -b 书籍ID --load-timeout 120

# 设置较短的超时时间（网络较好时）
weread-exporter -b 书籍ID --load-timeout 30
```

`--load-interval` 参数设置加载不同章节之间的间隔时间，单位为秒，默认值是 30 秒。设置间隔时间可以减轻服务器压力，避免被识别为爬虫行为。

```bash
# 增加间隔时间，降低请求频率
weread-exporter -b 书籍ID --load-interval 60

# 减少间隔时间，提高导出速度
weread-exporter -b 书籍ID --load-interval 10
```

这两个参数的关系是：`load-timeout` 控制单次加载的最长等待时间，`load-interval` 控制两次加载之间的等待时间。在网络环境较差时，建议同时增加两个参数的值。

### 1.2.3 浏览器参数

这些参数控制 Chrome 浏览器的行为，包括是否显示窗口、是否模拟用户登录、是否使用默认浏览器配置等。

`--headless` 参数让 Chrome 在无头模式下运行，即不显示浏览器窗口。无头模式占用资源更少，适合在服务器或后台运行。默认情况下，Chrome 会显示窗口，这有助于观察导出过程。

```bash
# 无头模式运行
weread-exporter -b 书籍ID --headless

# 显示浏览器窗口（默认行为）
weread-exporter -b 书籍ID
```

`--force-login` 参数强制进行登录操作，即使已有有效的 cookie 也会重新登录。这在你需要切换账号或登录状态异常时有用。

```bash
# 强制重新登录
weread-exporter -b 书籍ID --force-login
```

`--use-default-profile` 参数使用 Chrome 的默认用户配置而不是新建配置。这可以保留你的浏览器历史、书签、扩展等数据，但也可能带来隐私问题。

```bash
# 使用默认配置
weread-exporter -b 书籍ID --use-default-profile
```

`--mock-user-agent` 参数使用模拟的 User-Agent 字符串。这可以帮助绕过一些基于 User-Agent 的检测机制。

```bash
# 使用模拟 User-Agent
weread-exporter -b 书籍ID --mock-user-agent
```

### 1.2.4 代理参数

`--proxy-server` 参数用于指定 HTTP 代理服务器。当你需要通过代理访问微信读书时（如网络环境限制），需要设置此参数。代理格式为 `http://ip:port`。

```bash
# 使用代理
weread-exporter -b 书籍ID --proxy-server http://127.0.0.1:7890
```

需要注意的是，代理设置仅影响工具直接发起的 HTTP 请求，不影响 Chrome 浏览器的网络访问。如果需要浏览器也通过代理，需要单独配置 Chrome 的代理设置。

### 1.2.5 样式参数

`--css-file` 参数用于指定自定义 CSS 样式文件。这对于需要特殊排版效果的用户很有用，比如企业品牌定制或个人偏好设置。

```bash
# 使用自定义 CSS
weread-exporter -b 书籍ID --css-file custom.css
```

自定义 CSS 的作用范围包括 EPUB 和 PDF 导出中的样式覆盖。你可以通过 CSS 控制字体、字号、颜色、边距等视觉属性。需要注意的是，自定义 CSS 主要影响 PDF 导出的渲染，EPUB 格式的样式控制能力有限。

### 1.2.6 信息查询参数

这些参数用于查询信息而不进行导出操作，对于需要先了解书单内容或书籍列表的场景很有用。

`--list-booklists` 参数列出当前用户可见的所有书单。使用此参数不需要指定书籍 ID，会启动浏览器让你登录，然后显示书单列表。

```bash
# 列出所有书单
weread-exporter --list-booklists
```

`--list-ids` 参数与书单 ID 配合使用，列出书单中包含的所有书籍及其 ID。这在需要选择性地导出书单中的部分书籍时很有用。

```bash
# 列出书单中的所有书籍
weread-exporter -b 书单ID --list-ids
```

输出格式为：书籍标题、原始 ID、哈希 ID。通过这些信息，你可以选择特定的书籍单独导出。

### 1.2.7 参数组合使用示例

了解了各个参数的含义后，灵活组合参数可以满足各种复杂需求。以下是几个实用的参数组合示例：

**示例一：批量导出书单中的所有书籍，使用代理，并行导出多本**

```bash
# 首先查看书单内容
weread-exporter -b 12345_67890 --list-ids

# 然后导出整个书单（默认导出 EPUB）
weread-exporter -b 12345_67890 -o epub
```

**示例二：导出 PDF 格式，打印质量，添加自定义样式**

```bash
weread-exporter -b 书籍ID \
    -o pdf \
    --load-timeout 120 \
    --load-interval 45 \
    --css-file custom.css \
    --headless
```

**示例三：调试模式导出，观察完整过程**

```bash
weread-exporter -b 书籍ID \
    -o epub \
    --headless=false \
    --force-login \
    --load-timeout 120
```

这个配置会显示浏览器窗口，便于观察导出过程。适合排查问题或首次使用时了解工作原理。

## 1.3 输出目录与文件管理

理解 weread-exporter 的文件组织和缓存机制，有助于你更好地管理导出的文件。本节将详细介绍输出目录结构、缓存机制，以及如何在不同场景下进行文件管理。

### 1.3.1 输出目录结构

weread-exporter 将所有输出文件保存在 `output/` 目录下。每次导出的文件都会保存在这个目录中，按照书籍标题命名。

```
output/
├── 书籍标题.epub
├── 书籍标题.pdf
├── 书籍标题.md
└── 书籍标题.txt
```

如果导出文件已存在，工具会跳过导出操作并显示提示信息。这是出于安全考虑，避免意外覆盖已有文件。如果确实需要重新导出，需要先手动删除已有文件。

### 1.3.2 缓存目录结构

weread-exporter 在 `cache/` 目录下维护缓存数据，包括 cookie 文件、书籍元数据、章节内容、图片资源等。这些数据用于加速重复导出和离线访问。

```
cache/
├── cookie.txt          # 登录 cookie
├── 书籍ID/
│   ├── meta.json      # 书籍元数据
│   ├── cover.jpg      # 封面图片
│   ├── chapters/      # 章节 Markdown 文件
│   │   ├── 1-章节ID.md
│   │   └── 2-章节ID.md
│   └── images/        # 图片资源
│       ├── 图片1.jpg
│       └── 图片2.jpg
└── resources/         # 缓存的远程资源
    └── ...
```

理解缓存目录的作用后，你可以利用缓存实现一些高级操作。例如，如果已经导出了一次，可以只修改 CSS 样式重新生成 PDF 而不必重新抓取内容。又如，如果图片下载失败，可以手动下载后放入 images 目录。

### 1.3.3 缓存策略

weread-exporter 采用智能缓存策略以提高效率。已缓存的数据在下次导出会被复用，避免重复下载和处理。但这个策略也可能导致使用旧数据的问题，所以了解缓存机制很重要。

默认情况下，章节 Markdown 文件如果已存在且大小大于 3 字节，工具会跳过该章节的处理。这意味着如果第一次导出时某章节失败，后来手动修复了章节文件，第二次导出时会直接使用缓存。

如果遇到缓存导致的问题，可以手动清理相关缓存。有几种清理方式：删除特定书籍的缓存目录会完全重新抓取该书籍；删除 cookie.txt 会强制重新登录；删除整个 cache 目录会清除所有缓存。

```bash
# 清理特定书籍的缓存
rm -rf cache/书籍ID

# 清理 cookie（下次运行会重新登录）
rm cache/cookie.txt

# 清理所有缓存
rm -rf cache/*
```

## 1.4 书籍类型处理

不同类型的书籍可能需要不同的处理方式。本节将介绍几类特殊书籍的处理方法，包括漫画书、包含大量代码的技术书、有特殊排版的书籍等。

### 1.4.1 普通文字书籍

普通文字书籍是 weread-exporter 最擅长处理的对象。这类书籍以文字为主，结构清晰，导出效果通常最好。

导出建议：默认参数即可获得良好效果。如果追求最佳 PDF 质量，可以增加 `--load-timeout` 给页面更多加载时间。

### 1.4.2 漫画书与图文混排书籍

漫画书和图文混排书籍的特点是图片密集，对图片处理能力要求较高。weread-exporter 能够正确提取和保存图片，但某些特殊处理需要注意。

导出建议：确保网络稳定，以便图片能够完整下载。如果图片很多，导出时间会较长，建议增加 `--load-interval` 以避免触发服务器限制。PDF 格式最适合此类书籍，因为它能保持图片的原始尺寸和位置关系。

### 1.4.3 技术书籍与代码密集型书籍

技术书籍通常包含大量代码块、表格、公式等特殊内容。weread-exporter 能够正确识别和处理这些元素，但在不同输出格式中效果有所差异。

代码块处理：weread-exporter 会将代码块正确提取为 Markdown 代码块语法。EPUB 和 PDF 导出时会保留代码的格式，但具体显示效果取决于阅读器对代码块的支持程度。Markdown 导出时保留完整的代码块语法，可以用任何 Markdown 编辑器处理。

表格处理：复杂表格在 EPUB 中可能显示效果不佳，PDF 格式能更好地还原表格结构。如果表格内容非常重要，建议同时导出 PDF 版本以确保数据完整性。

公式处理：weread-exporter 本身不处理数学公式，如果书籍使用图片展示公式，图片会被正确提取；如果是内嵌公式，可能无法正确导出。

### 1.4.4 有声书与音视频内容

weread-exporter 只处理文字内容，不支持导出有声书的音视频部分。如果书籍附带音频或视频，这些内容不会包含在导出文件中。

## 1.5 导出质量优化

获得高质量的导出结果需要一些技巧和注意事项。本节将分享优化导出质量的实用建议，帮助你在不同场景下获得最佳效果。

### 1.5.1 网络稳定性

网络稳定性是影响导出质量的首要因素。网络波动可能导致页面加载不完整、图片下载失败、章节丢失等问题。

优化建议：选择网络最稳定的时间段进行导出；在网络较慢时增加 `--load-timeout` 参数值；使用有线网络而非无线网络；避免在网络高峰期导出大量书籍。

### 1.5.2 图片处理优化

图片是导出过程中最容易出问题的环节之一。图片问题包括下载失败、格式错误、引用失效等。

优化建议：确保 `--load-interval` 设置合理，给服务器足够响应时间；对于图片较多的书籍，优先使用 PDF 格式；导出后检查 images/ 目录，确认图片完整下载；如发现图片缺失，可以手动下载后放入对应目录。

### 1.5.3 样式调优

默认样式适用于大多数情况，但有时需要自定义样式以获得更好的效果。weread-exporter 允许通过 CSS 文件自定义 PDF 和 EPUB 的样式。

常用样式调整示例：

```css
/* 自定义字体 */
body {
    font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
}

/* 调整代码块样式 */
pre {
    background-color: #f5f5f5;
    padding: 10px;
    border-radius: 5px;
}

/* 调整图片最大宽度 */
img {
    max-width: 100%;
    height: auto;
}
```
