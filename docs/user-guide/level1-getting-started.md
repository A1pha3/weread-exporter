> 本文档是用户路径的第一篇，面向从未使用过 weread-exporter 的新手读者。通过阅读和实践本文档，你将在 30 分钟内完成工具的安装配置，并成功导出第一本书籍。

## 1.1 准备工作

在开始安装之前，我们需要确保你的系统满足基本要求。这些准备工作看似简单，但却是顺利使用工具的基础。很多安装问题实际上并非工具本身的问题，而是环境配置不当导致的。因此，请认真完成本节的每一步检查。

### 1.1.1 系统要求检查

weread-exporter 可以在 Windows、macOS 和 Linux 三大主流操作系统上运行，但不同系统可能需要不同的准备工作。在开始之前，请确认你的系统满足以下最低要求：

操作系统方面，Windows 用户需要 Windows 10 或更高版本，macOS 用户需要 10.15 或更高版本，Linux 用户推荐 Ubuntu 18.04 或同等水平的发行版。较老的操作系统版本可能会遇到兼容性问题，虽然并非所有功能都会受影响，但建议使用较新的系统版本以获得最佳体验。

Python 版本方面，工具要求 Python 3.7 或更高版本。你可以通过在终端输入 `python --version` 或 `python3 --version` 来检查当前安装的 Python 版本。如果你的系统没有安装 Python，或者版本低于 3.7，需要先从 Python 官方网站（https://www.python.org/downloads/）下载并安装最新版本。安装时请勾选「Add Python to PATH」选项，这将为后续操作提供便利。

内存方面，工具最低要求 4GB 可用内存，但推荐使用 8GB 或更多。导出过程中需要同时运行 Chrome 浏览器和 Python 程序，内存不足可能导致程序崩溃或导出失败。如果你打算批量导出多本书籍，建议预留更多内存空间。

磁盘空间方面，你需要至少 1GB 的可用空间来存放工具本身、缓存文件和导出结果。如果你的书籍包含大量图片，导出文件可能会更大，请根据实际需要预留足够的磁盘空间。

### 1.1.2 Chrome 浏览器安装

weread-exporter 的核心功能依赖 Chrome 浏览器进行内容渲染，因此安装 Chrome 是必要步骤。Chrome 是免费浏览器，你可以从官方网站（https://www.google.com/chrome/）下载安装包。

安装完成后，请确认 Chrome 已经正确安装并且可以在命令行中调用。你可以通过在终端输入 `chrome --version`（Windows）或 `google-chrome --version`（Linux）或 `/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --version`（macOS）来验证安装。如果命令返回版本信息，说明 Chrome 已经正确安装。

如果命令提示找不到 chrome，请检查 Chrome 的安装路径是否已经添加到系统 PATH 环境变量中。Windows 用户通常不需要额外配置，macOS 和 Linux 用户可能需要手动添加。Chrome 的常见安装路径包括：Windows 的 `C:\Program Files\Google\Chrome\Application\chrome.exe`，macOS 的 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，Linux 的 `/usr/bin/google-chrome` 或 `/usr/bin/google-chrome-stable`。

### 1.1.3 网络环境准备

weread-exporter 需要访问来微信读书的网站获取书籍内容，因此你需要确保网络环境能够正常访问 https://weread.qq.com。如果你在访问该网站时遇到困难，可能需要检查网络设置或使用代理。

在某些网络环境下，你可能需要配置代理服务器才能访问微信读书。weread-exporter 支持通过 `--proxy-server` 参数指定代理地址。代理地址的格式为 `http://ip:port`，例如 `http://127.0.0.1:7890`。如果你不确定如何获取代理地址，请咨询你的网络管理员或代理服务提供商。

需要注意的是，代理设置仅影响工具与微信读书服务器之间的通信，不会影响 Chrome 浏览器的网络访问。如果代理设置后仍然无法正常访问，可能需要为 Chrome 单独配置代理，或者检查代理服务的可用性。

## 1.2 安装 weread-exporter

完成准备工作后，我们开始安装 weread-exporter 工具本身。安装过程非常简单，只需要几个命令即可完成。本节将分别介绍通过 pip 安装和从源码安装两种方式，你可以根据自己的需求选择其中一种。

### 1.2.1 通过 pip 安装（推荐）

pip 是 Python 的标准包管理工具，通过它安装是最简单的方式。打开终端（Windows 用户可以使用命令提示符或 PowerShell），输入以下命令：

```bash
pip install weread-exporter
```

如果你的系统同时安装了 Python 2 和 Python 3，可能需要使用 pip3 命令：

```bash
pip3 install weread-exporter
```

安装过程中，pip 会自动下载并安装 weread-exporter 及其所有依赖包。这个过程通常需要几分钟时间，具体取决于你的网络速度。安装完成后，你可以通过以下命令验证安装是否成功：

```bash
weread-exporter --help
```

如果命令返回工具的使用帮助信息，说明安装已经成功。帮助信息会显示工具的版本号、支持的命令行参数以及基本用法。如果提示「command not found」或类似错误，请检查 pip 是否正确安装，以及工具是否已经添加到系统 PATH 中。

### 1.2.2 从源码安装

如果你需要修改工具源码、调试问题或者使用最新开发版本，可以从源码安装。首先需要克隆项目仓库：

```bash
git clone https://github.com/drunkdream/weread-exporter.git
cd weread-exporter
```

然后使用 pip 进行安装：

```bash
pip install -e .
```

`-e` 参数表示「可编辑」模式安装，这意味着你对源码的修改会直接反映到安装的工具中，非常适合开发调试场景。从源码安装时，所有依赖包需要单独安装，如果遇到依赖问题，可能需要手动解决。

从源码安装还需要确保系统中安装了 Git 工具。如果你还没有安装 Git，可以从 Git 官方网站（https://git-scm.com/）下载安装。

### 1.2.3 验证安装结果

无论通过哪种方式安装，都建议通过以下步骤验证安装是否完全成功。第一步是检查工具是否可以正常启动：

```bash
weread-exporter --version
```

这个命令应该返回工具的版本号，例如 `weread-exporter 1.0.0`。版本信息确认工具的基本功能正常。

第二步是检查核心依赖是否正确安装。主要需要验证 Python 环境正常、Chrome 浏览器可访问、以及所有 Python 依赖包都已正确安装。你可以通过导入关键模块来验证：

```bash
python -c "import weread_exporter; print('导入成功')"
```

如果以上所有检查都通过，说明安装已经完全成功，你可以进入下一节开始使用工具了。

## 1.3 获取书籍 ID

在使用工具导出书籍之前，我们需要先获取要导出的书籍 ID。书籍 ID 是微信读书中每本书的唯一标识符，从书籍的 URL 地址中可以提取。本节将详细介绍如何获取书籍 ID，包括从网页 URL 获取和从书单中获取两种方式。

### 1.3.1 从网页 URL 获取

打开微信读书网站（https://weread.qq.com/），登录你的账号后，找到你想要导出的书籍。点击书籍封面进入详情页面，此时浏览器地址栏显示的 URL 就包含了书籍 ID。

URL 的格式通常如下：

```
https://weread.qq.com/web/bookDetail/08232ac0720befa90825d88
```

其中 `08232ac0720befa90825d88` 就是这本书的书籍 ID。你需要复制这个 ID 部分用于后续的导出命令。注意不同书籍的 ID 长度可能不同，但格式都是类似的哈希字符串。

如果你的浏览器显示的是短链接格式，可以先将短链接展开，或者在书籍详情页面刷新后查看完整的 URL。

### 1.3.2 理解书单 ID

除了单本书籍，weread-exporter 还支持导出整个书单。书单是微信读书中用户整理的书籍集合，每个书单也有唯一的 ID。

书单 URL 的格式如下：

```
https://weread.qq.com/misc/booklist/12345_67890
```

注意书单 ID 通常包含下划线 `_`，这是区别于普通书籍 ID 的重要特征。在使用 weread-exporter 时，工具会自动识别包含下划线的 ID 为书单 ID，并采取相应的处理方式。

导出书单时，默认会导出书单中的所有书籍。如果你只想导出书单中的部分书籍，可以使用 `--list-ids` 参数先列出所有书籍的 ID，然后再分别导出。

## 1.4 第一次导出

现在你已经完成了所有准备工作，可以开始第一次导出了。本节将以导出 EPUB 格式为例，详细讲解整个导出流程。EPUB 是最通用的电子书格式，几乎所有电子书阅读器都支持。

### 1.4.1 登录微信读书

weread-exporter 在导出书籍时需要访问你的微信读书账号信息，因此需要先登录。工具通过 cookie 文件保存登录状态，首次使用时需要进行登录操作。

登录过程会自动启动 Chrome 浏览器窗口，你需要按照正常的微信读书登录流程完成登录。如果指定了 `--headless` 参数，浏览器将以无头模式运行，不会显示窗口，但仍然需要登录。

登录成功后，工具会将登录状态保存到 `cache/cookie.txt` 文件中。下次运行时可以直接使用保存的登录状态，无需再次登录。如果登录状态过期或失效，工具会提示你重新登录。

### 1.4.2 执行导出命令

在终端中执行以下命令来导出书籍：

```bash
weread-exporter -b 你的书籍ID -o epub
```

将 `你的书籍ID` 替换为你在 1.3 节获取的实际 ID。例如：

```bash
weread-exporter -b 08232ac0720befa90825d88 -o epub
```

导出过程会经历以下阶段：首先启动 Chrome 浏览器并访问书籍页面，然后加载章节内容并提取为 Markdown 格式，接着处理图片资源并下载到本地，最后将所有内容转换为 EPUB 格式。整个过程是自动的，你只需要耐心等待。

导出完成后，生成的文件会保存在 `output` 目录下，文件名为书籍标题加上 `.epub` 后缀。你可以在这个目录中找到生成的文件。

### 1.4.3 指定多种输出格式

weread-exporter 支持同时导出多种格式，你可以通过多次使用 `-o` 参数来指定：

```bash
weread-exporter -b 你的书籍ID -o epub -o pdf -o md
```

这个命令会同时生成 EPUB、PDF 和 Markdown 三种格式的文件。每种格式都会单独生成一个文件，保存在 output 目录中。

支持的格式包括：epub（通用电子书格式）、pdf（便携文档格式）、mobi（Kindle 专用格式）、txt（纯文本格式）、md（Markdown 标记语言格式）。导出 MOBI 格式时，工具会同时生成 EPUB 文件，然后转换为 MOBI。

### 1.4.4 验证导出结果

导出完成后，你需要验证生成的文件是否正确。首先检查 output 目录中是否生成了预期的文件：

```bash
ls -la output/
```

每个导出的格式都会生成一个独立的文件。文件命名规则为 `书籍标题.格式后缀`，例如 `Python编程快速上手.epub`。

对于 EPUB 文件，你可以尝试用电子书阅读软件打开它，检查内容是否完整、格式是否正确。对于 PDF 文件，可以直接用 PDF 阅读器打开验证。Markdown 文件是纯文本格式，可以用任何文本编辑器打开查看。

如果发现文件内容不完整或格式有问题，可能是导出过程中出现了错误。请检查终端输出中的日志信息，看看是否有错误或警告提示。这些信息可以帮助你定位问题原因。

## 1.5 导出流程详解

理解导出的工作流程有助于你更好地使用工具，并在遇到问题时更快定位原因。本节将详细介绍 weread-exporter 的完整工作流程，包括每个阶段的执行内容和可能遇到的问题。

### 1.5.1 浏览器初始化阶段

导出过程的第一步是启动 Chrome 浏览器实例。工具使用 Pyppeteer 库来控制 Chrome，这是一个基于 Puppeteer 的 Python 移植版本。浏览器实例的启动包括多个步骤：首先是检查 Chrome 是否正确安装，然后设置浏览器参数如窗口大小、是否无头模式等，最后注入反检测脚本来伪装浏览器环境。

反检测脚本的作用是让微信读书的网站无法识别你使用的是自动化工具。脚本会修改 `navigator.webdriver`、`navigator.plugins`、`navigator.languages` 等属性，使其看起来像普通用户使用的浏览器。这是必要的步骤，因为一些网站会检测自动化访问并采取限制措施。

浏览器启动后，工具会检查登录状态。如果没有有效的 cookie 文件，或者登录状态已过期，工具会启动登录流程。登录成功后，cookie 会被保存到 `cache/cookie.txt` 文件中，供后续使用。

### 1.5.2 页面加载与内容提取

浏览器初始化完成后，会导航到书籍详情页面并开始加载章节内容。weread-exporter 使用 Canvas Hook 技术来提取内容，这是一种比传统网页爬取更可靠的方法。

传统的网页爬取方法是解析 HTML 源代码，但微信读书的内容是通过 JavaScript 动态渲染的，HTML 源代码中并不包含实际内容。Canvas Hook 的原理是拦截 Canvas 渲染过程，在内容被绘制到画布之前提取原始数据。这样即使网站使用了复杂的反爬措施，依然能够获取完整内容。

内容提取过程中，工具会遍历书籍的所有章节，逐页加载并提取内容。每个章节提取完成后，会保存为独立的 Markdown 文件。章节文件保存在 `cache/书籍ID/chapters/` 目录下。

### 1.5.3 资源处理与格式转换

提取完所有章节内容后，工具会进行资源处理和格式转换。资源处理主要包括图片下载和路径替换。书籍中的图片会被下载到 `cache/书籍ID/images/` 目录，Markdown 文件中的图片引用会被更新为本地路径。

格式转换是导出的最后一步。工具使用 EbookLib 库将 Markdown 文件转换为 EPUB 格式，使用 WeasyPrint 库将内容渲染为 PDF。转换过程中会应用 CSS 样式文件，确保输出文件的视觉效果与原书一致。

对于 MOBI 格式，工具会先生成 EPUB 文件，然后使用 Amazon 的 kindlegen 工具进行转换。kindlegen 只在 Linux 平台提供，如果在其他平台上导出 MOBI 格式，工具会显示相应提示。

### 1.5.4 错误处理与重试机制

导出过程中可能会遇到各种错误，如网络超时、页面加载失败、登录状态失效等。weread-exporter 实现了完善的错误处理和重试机制，以提高导出成功率。

对于章节加载错误，工具会进行最多三次重试。每次重试前会关闭当前浏览器实例并重新启动，以清除可能的问题状态。如果三次重试都失败，工具会跳过该章节并继续处理后续章节，同时在日志中记录错误信息。

如果遇到登录状态失效错误，工具会提示用户重新登录。用户需要手动完成登录流程，登录成功后工具会继续导出过程。

其他类型的错误会根据具体情况进行处理。一些瞬时错误（如网络波动）会自动重试，而持久性错误（如书籍已下架）则会被记录并终止导出。

## 1.6 常见问题与解决方案

本节汇总了使用 weread-exporter 时最常见的问题及其解决方案。如果你在使用过程中遇到问题，请先查阅本节内容，很可能能找到答案。

### 1.6.1 安装相关问题

问题一：pip 安装失败，提示找不到包。解决方案：首先检查网络连接是否正常，然后尝试使用国内镜像源：`pip install weread-exporter -i https://pypi.tuna.tsinghua.edu.cn/simple/`。如果仍然失败，可能是 pip 版本过旧，尝试升级 pip：`pip install --upgrade pip`。

问题二：Chrome 找不到或版本不匹配。解决方案：确认 Chrome 已经正确安装，并且可以在命令行中调用。如果 Chrome 不在系统 PATH 中，可以通过设置 `CHROMIUM_PATH` 环境变量指定其路径。Windows 用户还需要确保系统 DLL 搜索路径正确配置。

问题三：依赖包安装失败。weread-exporter 的依赖包较多，某些依赖可能在特定系统上编译失败。最常见的问题是 WeasyPrint 依赖的 Cairo 库。Windows 用户建议使用预编译的 wheel 包，macOS 用户建议使用 Homebrew 安装依赖，Linux 用户建议按照 WeasyPrint 官方文档安装系统依赖。

### 1.6.2 运行相关问题

问题一：命令执行后没有任何输出。解决方案：首先检查是否正确安装了工具：`weread-exporter --version`。然后检查 Python 环境是否正确。如果工具可以正常显示帮助信息但执行导出没有输出，可能是日志级别设置问题，尝试添加 `-v` 参数显示详细日志。

问题二：导出失败，提示书籍不存在或已下架。解决方案：确认你使用的是正确的书籍 ID，并且书籍仍然在微信读书平台上。如果书籍已经下架或设置为私密，将无法导出。

问题三：登录后立即显示未登录状态。解决方案：这通常是因为 cookie 格式不正确或已过期。尝试删除 `cache/cookie.txt` 文件，然后重新运行工具进行登录。如果问题持续，可能是微信读书更新了登录验证机制，需要等待工具适配更新。

### 1.6.3 输出质量相关问题

问题一：导出的 EPUB 文件图片显示异常。解决方案：检查 `cache/书籍ID/images/` 目录下是否有对应的图片文件。如果图片下载失败，可能是网络问题导致图片资源无法访问。尝试使用代理服务器或检查网络连接。

问题二：章节顺序错乱或不完整。解决方案：这通常是因为章节加载超时或失败。尝试增加超时时间参数：`weread-exporter -b 你的书籍ID --load-timeout 120`。如果某些特定章节持续失败，可能是该章节内容特殊导致解析问题，可以在日志中查看详细信息。

问题三：导出格式与预期不符。解决方案：确认你使用的是正确的输出格式参数。每种格式需要不同的依赖支持，缺失某些依赖可能导致格式转换失败。检查终端输出中的错误信息，根据提示安装缺失的依赖。
